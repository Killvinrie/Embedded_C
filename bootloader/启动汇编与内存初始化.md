# STM32F411 启动汇编与内存初始化

## 启动文件

典型 GCC 工程：`startup_stm32f411xe.s`。

```asm
.syntax unified
.cpu cortex-m4
.thumb

.section .isr_vector,"a",%progbits
.word _estack
.word Reset_Handler
.word NMI_Handler
.word HardFault_Handler
```

- `.syntax`、`.cpu`、`.thumb` 是汇编器伪指令。
- `.word` 表示放置 32 位数据；它不是函数调用。
- `.isr_vector` 是向量表段；链接脚本通常通过 `KEEP(*(.isr_vector))` 保留它。

## Reset_Handler 的典型任务

1. 设置/确认 SP（硬件复位时 MSP 已自动加载）。
2. 将 `.data` 初始值由 Flash 复制到 SRAM。
3. 将 `.bss` 对应 SRAM 清零。
4. 调用 `SystemInit()` 初始化基本系统环境。
5. 调用 `__libc_init_array()` 处理 C/C++ 运行时初始化。
6. 调用 `main()`。

> [!note] 顺序说明
> 不同工具链、不同启动文件的初始化顺序会有差异；应以当前工程的 `startup_*.s` 为准。

## .data 与 .bss

```c
int initialized = 100; // 通常在 .data：Flash 存初值，运行在 SRAM
int counter;           // 通常在 .bss：启动时清零
static int errors;     // 通常在 .bss：启动时清零
```

| 段 | 作用 | 启动动作 |
|---|---|---|
| `.isr_vector` | 向量表 | 链接时放到指定地址 |
| `.text` | 程序指令 | 通常直接从 Flash 执行 |
| `.rodata` | 常量 | 通常在 Flash |
| `.data` | 有初值的可写静态数据 | Flash → SRAM 复制 |
| `.bss` | 零初始化静态数据 | SRAM 清零 |

`_sidata` 是 `.data` 的 Flash 装载源；`_sdata`、`_edata` 是 SRAM 目标边界；`_sbss`、`_ebss` 是清零范围。

## OTA 中的直接影响

- App A/B 都必须执行**自己的** `Reset_Handler`，完成各自的 `.data/.bss` 初始化。
- 不能从 Bootloader 直接跳到 App 的 `main()`。
- App 写在普通 `.data/.bss` 的标志在复位或启动后可能被覆盖；跨复位标志应采用设计好的备份寄存器、保留 RAM 区或 Flash Metadata。

## Ubuntu 查看 ELF

```bash
arm-none-eabi-objdump -h build/app_A.elf
arm-none-eabi-objdump -s -j .isr_vector build/app_A.elf
arm-none-eabi-nm build/app_A.elf | grep Reset_Handler
```
