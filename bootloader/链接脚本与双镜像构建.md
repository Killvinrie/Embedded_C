# A/B Bank 链接脚本与双镜像构建

## 为什么同一份源码要编译两个 BIN？

普通裸机 STM32 固件一般不是位置无关代码。链接器会确定中断向量表、常量与函数等地址。将为 A 链接的 BIN 直接复制到 B，不会自动重定位其中所有绝对地址。

因此，当前**原地执行两槽方案**采用：一份源码 + 两套链接配置。

## 链接配置（仅为 MEMORY 片段）

`app_A.ld`：

```ld
MEMORY
{
    RAM (xrw) : ORIGIN = 0x20000000, LENGTH = 128K
    FLASH (rx) : ORIGIN = 0x08010000, LENGTH = 192K
}
```

`app_B.ld`：

```ld
MEMORY
{
    RAM (xrw) : ORIGIN = 0x20000000, LENGTH = 128K
    FLASH (rx) : ORIGIN = 0x08040000, LENGTH = 192K
}
```

Bootloader：`FLASH ORIGIN=0x08000000, LENGTH=32K`。

> [!important] 注意
> 上面只是 `MEMORY` 片段，不能代替完整 `.ld` 文件；保留 `SECTIONS` 和启动符号。Bank B 的实际物理分区是 256KB，这里有意仅使用前 192KB。

## 编译宏区分 Bank

```c
#if defined(APP_BANK_A)
#define APP_VECTOR_ADDR 0x08010000U
#elif defined(APP_BANK_B)
#define APP_VECTOR_ADDR 0x08040000U
#else
#error "APP bank not defined"
#endif
```

`SystemInit()` 中相关 VTOR 配置也必须使用对应地址。

## 检查 ELF

```bash
arm-none-eabi-objdump -h app_A.elf
arm-none-eabi-objdump -h app_B.elf
arm-none-eabi-nm app_A.elf | grep Reset_Handler
arm-none-eabi-objcopy -O binary app_A.elf app_A.bin
stat -c %s app_A.bin
```

验收：A 的 `.isr_vector` 在 `0x08010000`，B 在 `0x08040000`，两份 BIN 均不超过 `196608` 字节（192KiB）。
