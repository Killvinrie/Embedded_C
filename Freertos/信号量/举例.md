
假设你的 STM32 通过 DMA 接收 ESP32 发送的串口数据。

DMA 接收完成时触发中断，通知解析任务处理数据。

```
SemaphoreHandle_t dmaSem;

void DMA_IRQHandler(void)
{
    BaseType_t xHigherPriorityTaskWoken = pdFALSE;

    // 清除 DMA 中断标志

    xSemaphoreGiveFromISR(
        dmaSem,
        &xHigherPriorityTaskWoken
    );

    portYIELD_FROM_ISR(xHigherPriorityTaskWoken);
}
```

解析任务：

```
void ParseTask(void *argument)
{
    while (1)
    {
        if (xSemaphoreTake(dmaSem, portMAX_DELAY) == pdTRUE)
        {
            ParseUARTData();
        }
    }
}
```

执行流程：

```
ESP32 发送数据
       |
       v
STM32 DMA 接收完成
       |
       v
DMA 中断
       |
       v
xSemaphoreGiveFromISR()
       |
       v
ParseTask 被唤醒
       |
       v
解析串口数据
```

这就是非常典型的 **ISR Give + Task Take** 模式。

其他类似场景包括 ADC 采样完成、SPI DMA 传输完成、传感器数据就绪中断等。

如果只是通知唯一一个任务，实际项目中通常可以优先考虑更轻量的直接任务通知。

# 一、场景一：TaskA Take，TaskB Give（任务同步）

假设你的无人机 OTA 系统有两个任务：

- `DownloadTask`：负责从树莓派下载固件到 ESP32。
- `UpgradeTask`：负责将下载好的固件发送给 STM32 Bootloader。

要求：**只有固件下载完成之后，才能开始升级。**

这时就可以使用二值信号量。



# 二、场景二：TaskA Take，TaskA Give（共享资源保护）

假设你的 STM32 无人机系统中有两个任务：

- `SensorTask`：访问 I²C 读取 MPU6050。
- `MonitorTask`：访问同一条 I²C 总线读取其他传感器。

因为两个任务共用同一个 I²C 外设，所以不能同时操作。

此时应该使用**互斥量（Mutex）**。
