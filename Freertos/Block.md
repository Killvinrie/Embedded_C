## Block 内存块结构

在 FreeRTOS 的 `heap_4.c` 内存管理方案中，堆内存通过内存块（Memory Block）进行管理。每个内存块通常由**管理头部（Block Header）和数据区域（Payload）**组成。

### 1. 管理头部

FreeRTOS 使用 `BlockLink_t` 结构体描述内存块的管理信息，其核心定义为：

```
typedef struct A_BLOCK_LINK
{
    struct A_BLOCK_LINK *pxNextFreeBlock;
    size_t xBlockSize;
} BlockLink_t;
```

- `**pxNextFreeBlock**`：指向空闲链表中的下一个空闲内存块。该字段主要在内存块处于空闲状态时使用。
    
- `**xBlockSize**`：记录内存块的总大小，包括管理头部及数据区域，并考虑内存对齐要求。在 `heap_4.c` 中，其最高位还用于标记内存块的分配状态。
    

### 2. 内存布局

以 32 位 STM32 为例，假设管理头部占用 8 字节：

```
低地址
┌──────────────────────────┐ ◄── BlockLink_t *
│ pxNextFreeBlock    (4B)  │
├──────────────────────────┤
│ xBlockSize         (4B)  │
├──────────────────────────┤ ◄── 用户指针
│                          │
│        数据区域          │
│        (Payload)         │
│                          │
└──────────────────────────┘
高地址
```

设管理头部大小为 (H)，实际分配的内存块大小为 (B)，则：

[  
B=H+P  
]

其中，(P) 是包含必要对齐填充的数据区域大小。

因此：

[  
P=B-H  
]

### 3. 内存分配与释放

**分配：**

`pvPortMalloc()` 从空闲链表中寻找满足要求的内存块，必要时进行分割，并将跳过管理头部后的地址返回给用户。

```c
void *pv = pvPortMalloc(100);
```

返回的 `pv` 指向数据区域，而不是管理头部。

**释放：**

```c
vPortFree(pv);
```

内存管理器根据用户指针向前定位管理头部，读取内存块大小等信息，将其重新插入空闲链表，并尝试合并地址相邻的空闲块，以减少外部内存碎片。

### 4. 核心结论

1. `BlockLink_t` 仅描述内存块的管理信息，并不直接包含整个数据区域。
    
2. 管理头部和数据区域在内存中连续存放。
    
3. `pvPortMalloc()` 返回数据区域的首地址，`vPortFree()` 通过该地址定位管理头部。
    
4. `xBlockSize` 表示包含管理开销的块大小，而不是用户申请的字节数。
    
5. `heap_4.c` 通过空闲链表管理内存块，并支持相邻空闲块合并。
