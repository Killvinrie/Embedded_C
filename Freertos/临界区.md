理解线程安全，必须理解临界区。

临界区是指：

**访问共享资源、且不能被其他并发执行单元干扰的一段代码。**

例如：

```
count++;
```

当多个任务共享 `count` 时，这条语句就涉及临界区。

FreeRTOS 提供了临界区保护接口：

```
taskENTER_CRITICAL();

/* 临界区 */
count++;

taskEXIT_CRITICAL();
```

在 STM32F411 的 Cortex-M4 FreeRTOS 端口中，通常使用 `BASEPRI` 寄存器屏蔽一定优先级范围的中断，以保护临界区。

其效果包括：

- 防止 FreeRTOS 任务在临界区内发生普通的抢占式切换。
- 屏蔽可以调用 FreeRTOS 中断安全 API 的那部分中断优先级范围。
- 高紧急程度的中断仍然可能执行。

因此，不能简单地认为进入临界区后 CPU 就不响应任何中断。

对于单核 STM32 的普通任务共享数据，这是一种有效的保护方法。

但是：

```c
taskENTER_CRITICAL();

HAL_Delay(100);   // 不应该这样做
printf("hello");  // 不建议
count++;

taskEXIT_CRITICAL();
```

临界区内不应该放入长时间运行、可能阻塞或等待中断的操作，否则会严重影响系统实时性，甚至导致死锁。

所以，**临界区应该尽可能短。**
