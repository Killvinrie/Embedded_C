# 嵌入式面试七天学习计划

这套笔记对应你列出的 **41 个问题**，按依赖关系安排成七天。目标是：能解释原理、读懂关键代码、分析故障，并把答案说成一段有依据的工程判断。

默认你已接触 C 和 MCU，每天能投入 **4 小时净学习时间**，共 28 小时；休息另计。没有开发板也能完成全部阅读、手算、电脑实验和故障推演。七天适合建立面试知识体系，不能替代真实项目调试经历。

## 如何在 Obsidian 使用

1. 将整个文件夹放进已有 Obsidian 仓库，或使用“打开文件夹作为仓库”打开它。
2. 从本页按顺序打开每天的双向链接。所有笔记均为 UTF-8 Markdown，无需安装插件。
3. 每天勾选任务，先独立回答自测，再展开答案。
4. `实验代码` 内是电脑可运行的 C 实验；涉及 MCU、FreeRTOS、ESP-IDF 的正文代码会标明适用环境或“伪代码”。

## 先统一几个前提

| 内容 | 本笔记采用的前提 |
|---|---|
| C 语言 | 以 C11 为主，不把 C++ 的 const、inline、联合体规则直接套过来 |
| 内存布局 | 示例明确假设常见 ABI；目标平台的 `sizeof`、`_Alignof`、`offsetof` 才是验证依据 |
| 调度 | 先按原生 FreeRTOS 单核讲解，单独说明 ESP-IDF SMP 差异 |
| PendSV、寄存器压栈 | 以 Cortex-M3/M4、常见 FreeRTOS GCC 移植为例；ESP32 不使用 Cortex-M PendSV |
| ESP32 | 以经典 ESP32、ESP-IDF **v5.2 文档**为固定示例基线，并非推荐最新版本；其他芯片和 IDF 版本需核对配置名、保留内存与接口 |
| 联网 | Wi-Fi 按 WPA2-Personal + IPv4 DHCP 主线；BLE 按常见广播/GATT；MQTT 按 3.1.1 |
| 项目表达 | 示例统一用“电池供电无线传感器”；这是练习场景，不代表你做过这个项目 |

## 面试回答的统一结构

**一句话结论 → 原理 → 场景/代码 → 限制与验证。**

例如：“ISR 中我只保存必要状态并发通知。因为阻塞和长计算会增加中断延迟，普通 RTOS API 也不满足 ISR 调用条件。解析和日志由任务处理；队列满时统计丢弃，并用逻辑分析仪验证 ISR 最长时间。”

没有做过的内容说“我理解的实现方案是……”或“我用练习验证过……”，不要把阅读材料包装成项目经历。

 volatile 什么场景必须加？中断标志位为什么一定要加？编译器不加会怎么优化？
- static 修饰局部变量、全局变量、函数分别什么效果？生命周期和作用域各自怎么变？
- const 和指针结合那几种写法分别什么意思？const 修饰的变量真的不能改吗？
- 结构体内存对齐讲一下，然后给了个结构体让我算大小，问怎么重排字段省内存
- 结构体和联合体的区别？联合体在嵌入式里一般拿来干嘛？
- 位域是什么？跨字节的位域怎么排？为什么协议解析里爱用它
- malloc 和静态数组，在 MCU 上你更倾向用哪个？为什么？
- 什么是内存碎片？为什么嵌入式里特别怕它？怎么规避
- 野指针和悬空指针的区别？free 之后要不要置 NULL
- 函数指针和回调，你项目里哪儿用到了？回调里能干耗时的事吗
- 大小端怎么判断？网络传输的时候为什么要关心字节序？
- inline 和宏的区别？inline 一定会展开吗
- 你项目里用了 SPI，讲一下 SPI 的时序，四种模式区别在哪？
- SPI 和 I2C 怎么选？各自的速率和线数
- 编译四个阶段分别干了啥？.h 里为什么不能定义变量
