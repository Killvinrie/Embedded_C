# 实验说明

[[00-开始这里|返回总计划]]

这些实验用来观察 C 语义和验证流式解析，不依赖开发板。需要已有 GCC 或兼容 C11 编译器；ARM 汇编观察额外需要 `arm-none-eabi-gcc`。命令均从本学习文件夹根目录执行。

| 文件 | 对应内容 | 预期结果 |
|---|---|---|
| [01_basics.c](01_basics.c) | static、const、inline、分配/释放 | 输出 PASS |
| [02_layout.c](02_layout.c) | 对齐、联合体、字节序、位解析 | 典型 ABI 下 12→8，union 为 8；字段 type=5、value=291 |
| [03_volatile.c](03_volatile.c) | 优化后的轮询加载 | 生成汇编；观察两种循环内加载差别，不运行 |
| [05_stream_parser.c](05_stream_parser.c) | TCP 应用层增量分帧 | 1024 种分片组合和边界检查通过 |

## 构建并运行

```bash
gcc -std=c11 -Wall -Wextra -Wpedantic -O2 实验代码/01_basics.c -o /tmp/embedded_basics
/tmp/embedded_basics
gcc -std=c11 -Wall -Wextra -Wpedantic -O2 实验代码/02_layout.c -o /tmp/embedded_layout
/tmp/embedded_layout
gcc -std=c11 -Wall -Wextra -Wpedantic -O2 实验代码/05_stream_parser.c -o /tmp/embedded_stream
/tmp/embedded_stream
gcc -std=c11 -O2 -S 实验代码/03_volatile.c -o /tmp/embedded_volatile.s
```

`/tmp` 是临时输出位置。Windows 原生终端需调整输出路径和可执行文件名，也可在 WSL 中使用以上命令。

若工具链支持，可对解析器增加内存与未定义行为检查：

```bash
gcc -std=c11 -Wall -Wextra -Wpedantic -g -O1 -fsanitize=address,undefined -fno-omit-frame-pointer 实验代码/05_stream_parser.c -o /tmp/embedded_stream_checked
/tmp/embedded_stream_checked
```

## 看汇编时要找什么

普通循环可能先加载一次，然后在寄存器/固定分支中等待；volatile 循环通常会把加载留在循环内。汇编标签和指令因 CPU/编译器而异，观察控制流和加载位置，不要背某段汇编文本。

```bash
arm-none-eabi-gcc -mcpu=cortex-m4 -mthumb -std=c11 -O2 -S 实验代码/03_volatile.c -o /tmp/embedded_volatile_arm.s
```

## 验证边界

- PC 上的布局结果只验证当前 ABI；实验里的静态断言说明所需前提，不代表所有 MCU 都相同。
- 解析器检查只覆盖分帧和边界行为，网络超时、TLS、并发及业务去重仍由工程实现。
- 正文的 MCU/RTOS 片段用于解释机制，需要目标工程中的头文件、对象创建、驱动和配置；没有在真实开发板上验证。
- 不包含 OTA 烧录、改写分区或 eFuse 的自动执行脚本。

## 本次实际验证记录

2026-11-10，使用主机 GCC 15.2.0：三个可执行实验均通过 `-Wall -Wextra -Wpedantic -Werror -O2` 编译并运行。解析器通过全部 1024 种示例流分片组合，以及最大长度、零长度、非法长度和断线重置检查。

解析器也通过 AddressSanitizer 与 UndefinedBehaviorSanitizer 检查。本运行环境的 LeakSanitizer 因 ptrace 限制无法运行，因此验证时设 `ASAN_OPTIONS=detect_leaks=0`，未声称完成泄漏检测；解析器本身没有动态分配。普通本机环境可先按上面的默认命令执行，无需预先关闭泄漏检查。

使用 ARM GCC 14.2.1 编译 Cortex-M4 `-O2` 汇编，实际观察到如下关键差别（省略地址初始化和符号细节）：

```asm
/* 普通变量：只在循环前加载 */
    ldr r3, [r3]
    cbz r3, .L3
    bx  lr
.L3:
    b   .L3

/* volatile 变量：每轮执行加载 */
.L8:
    ldr r3, [r2, #4]
    cmp r3, #0
    beq .L8
    bx  lr
```

以上仅是这次编译器与配置下的观察结果，不是要求所有工具链产生相同指令。
