## 60 分钟模拟面试

用 40 分钟回答下面 10 题，每题约 4 分钟；然后用 20 分钟看评分点，重讲最弱的 3 题。每题 0～3 分，总分 30。**24 分以上且没有关键概念错误**，可认为本轮复习达标；这不是岗位录用标准。

评分：0 分=不能解释或核心错误；1 分=能给定义；2 分=能讲机制与例子；3 分=能说明边界、故障路径和验证方法。

| 题目                                | 拿到 3 分要覆盖的内容                                       |
| --------------------------------- | -------------------------------------------------- |
| 1. ISR 设 ready，主循环轮询，-O2 后卡死，怎么查？ | 加载可能移出循环；volatile 的访问语义；原子性/丢事件仍需解决；看汇编与 RTOS 替代方案 |
| 2. 手算并重排结构体 `u8/u32/u16/u8`       | 说明 ABI 假设；偏移 0/4/8/10；大小 12→8；packed 的限制           |
| 3. 系统还有空闲堆但大申请失败                  | 总量与最大连续块；碎片/泄漏区别；内存池与生命周期；长期压力测试                   |
| 4. ISR 唤醒高优先级任务，直到任务运行发生什么？       | FromISR、优先级阈值、请求切换、Cortex-M PendSV、硬件/软件上下文、TCB 栈顶 |
| 5. H 等 L 的锁，M 一直运行，怎么处理？          | 优先级反转、继承提升 L、mutex 与信号量差异、短持锁、不能解决死锁               |
| 6. 接收端一次收半条或两条 TCP 消息，怎么办？        | 字节流、长度头/分隔符、增量状态、长度上限、多帧循环、断线重置                    |
| 7. 设备弱网每分钟重连很多次且耗电，如何设计？          | 分层定位、退避抖动、稳定窗口、单入口、有界缓存、统计与电量积分                    |
| 8. MQTT QoS 2 是否保证电机只转一次？         | 四报文与协议状态、保障范围、request_id、幂等/持久记录、业务完成确认            |
| 9. 深睡为什么丢变量？怎样实现一年续航？             | 普通 RAM/RTC/NVS、重新启动、容量→平均电流预算、联网能耗、硬件漏电            |
| 10. OTA 首启死锁并且配置已迁移，如何恢复？         | A/B、候选确认、看门狗、旧槽有效性、配置兼容/事务、防回退约束                   |

关键错误示例：volatile 等于线程安全；位域可直接映射所有协议；taskYIELD 保证低优先级运行；任何 ISR 都能用 FromISR；TCP 保留消息边界；QoS 2 保证任意业务副作用一次；普通 static 在深睡后自动保留；双分区绝对不会变砖。

## 41 题口述提示卡

| 题号  | 20 秒起手式                                                      |
| --- | ------------------------------------------------------------ |
| Q01 | volatile 保留必要的外部可见访问，防止错误省略轮询加载；不保证原子性/同步。                   |
| Q02 | 局部 static 改存储期；文件级 static 改链接性；static 函数限定本翻译单元。             |
| Q03 | 星号左边 const 限制通过指针改对象，右边 const 限制指针本身；真正 const 对象强写是未定义行为。    |
| Q04 | 按字段对齐逐个补齐，再按结构体对齐补尾部；重排减少间隙，目标 ABI 要验证。                      |
| Q05 | struct 各有存储，union 共享存储；用标签说明当前有效载荷。                          |
| Q06 | 位域按位宽声明，但布局依实现；协议解析用明确字节序与掩码移位。                              |
| Q07 | 关键路径优先静态资源/内存池，动态分配要有上限、失败处理及所有权。                            |
| Q08 | 外部碎片导致连续大块申请失败；内部碎片是块内浪费；合并不能消除全部碎片。                         |
| Q09 | 悬空指针指向生命周期已结束的对象；free 后置空只修一个指针变量，别名仍危险。                     |
| Q10 | 回调由调用方决定上下文；是否能耗时取决于 ISR、服务线程或业务线程及预算。                       |
| Q11 | 大小端是多字节数值的内存字节顺序；线上格式要约定，不能直接发本机对象表示。                        |
| Q12 | 宏是文本替换，inline 是函数语义加优化建议；inline 不保证展开。                       |
| Q13 | CPOL 管空闲电平，CPHA 管第一/第二沿采样；先确定首沿再推采样沿。                        |
| Q14 | SPI 常见四线、高吞吐、按设备限速；I2C 两线共享、带寻址与 ACK、常用 100k/400k。           |
| Q15 | 预处理、编译、汇编、链接；共享变量头文件 extern 声明、一个 C 文件定义。                    |
| Q16 | 单核运行最高优先级就绪任务；阻塞任务不参与就绪竞争。                                   |
| Q17 | 抢占处理不同优先级，时间片处理同级轮转；关闭时间片不等于禁止同级一切切换。                        |
| Q18 | 估最深调用链，测最坏路径与最小剩余栈，启用检测并留余量，先核对单位。                           |
| Q19 | 保存 CPU 上下文到任务栈，TCB 记栈顶，不复制整个 RAM。                            |
| Q20 | Cortex-M 常用最低优先级 PendSV 延后统一执行切换，ESP32 不套用。                  |
| Q21 | Idle 是最低优先级兜底任务，负责特定资源清理、Hook 与低功耗相关工作。                      |
| Q22 | H 等 L 的锁被 M 间接拖住，继承临时提升 L；天花板是预先约束资源优先级的协议。                  |
| Q23 | 队列传数据，信号量通知/计数，mutex 保护有所有权的资源；底层复用不等于语义相同。                  |
| Q24 | 二值信号量无所有者/继承，mutex 有任务所有权与继承，不能用于 ISR。                       |
| Q25 | ISR 不能像任务那样阻塞；FromISR 提供适合中断的访问路径，并受中断优先级约束。                 |
| Q26 | ISR 长操作增加延迟；普通 printf 可能锁、等待和占栈，记录短事件后任务输出。                  |
| Q27 | 临界区依移植屏蔽特定中断，多核还需跨核锁；扩大范围增加中断延迟。                             |
| Q28 | FreeRTOS 软件定时器共用服务任务，回调不能阻塞；硬件计数器适合更精确触发。                    |
| Q29 | 扫描、认证/关联、密钥握手、获取 IP，再到 DNS/TCP/TLS/业务认证；每层分别判断。              |
| Q30 | 状态机统一重连，分原因、退避加抖动、稳定后重置，缓存与尝试均有上限。                           |
| Q31 | TCP 有序可靠字节流，UDP 保留报文边界但无交付保证；业务确认与幂等另设计。                     |
| Q32 | TCP 无消息边界，用增量分帧并处理半包、多包、非法长度和断线。                             |
| Q33 | 广播用于发现/无连接数据；连接不等于配对，配对不等于保存绑定。                              |
| Q34 | GATT 将属性组织成服务和特征；描述符补充配置，通知/指示有不同 ATT 确认语义。                  |
| Q35 | QoS 0 至多、1 至少、2 协议范围内恰好一次；2 用四报文状态机而非业务万能去重。                 |
| Q36 | Light-sleep 保留执行相关状态，Deep-sleep 重启且普通 RAM 不保留，可按配置保留 RTC 数据。 |
| Q37 | 可用容量除以寿命得平均电流预算，再分阶段积分，优先优化最大能耗项。                            |
| Q38 | 下载到非活动槽，校验后提交启动选择，试运行通过才确认，旧版本保持可恢复。                         |
| Q39 | 双应用槽加可靠元数据；回滚要有有效旧镜像、兼容配置和允许的安全版本。                           |
| Q40 | 签名保证来源/完整性，加密保护机密性，安全启动形成信任链，防回退限制脆弱旧版。                      |
| Q41 | 依据关键任务有意义的进展喂狗；独立任务无条件喂可能掩盖业务死锁。                             |

## 高频数字与单位

| 项目 | 本计划使用的值/解释 |
|---|---|
| SPI 模式 | 0=00，1=01，2=10，3=11；二进制顺序 CPOL、CPHA |
| I2C 常见速率 | 100k、400kbit/s；1M、3.4M 需对应支持 |
| 原生 FreeRTOS 栈参数 | StackType_t 元素数，不能默认字节 |
| ESP-IDF v5.2 栈参数 | 相应接口按字节，具体读该版本说明 |
| ESP-IDF v5.2 经典 ESP32 高水位 | 本例 Xtensa 实现返回字节数，不再乘 4；Day 3 给出源码依据 |
| Cortex-M 任务优先级与中断优先级 | FreeRTOS 任务通常数值大更高；NVIC 中断逻辑数值小更紧急 |
| 传统 BLE 广播数据 | 常见 31B 限制不适用于所有扩展广播 |
| ATT MTU 23 的普通通知 | 常见有效特征值 20B，协商后可变 |
| 一年 | 非闰年按 8760h 估算 |
| ESP32 应用分区起始对齐 | 本例按 64KiB（0x10000） |
| 本例 otadata | 0x2000=8KiB，两个扇区 |
