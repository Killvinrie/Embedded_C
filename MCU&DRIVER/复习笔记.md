# 嵌入式面试复习笔记：I²C 与 SPI

> [!info] 学习目标  
> 本笔记面向 STM32、ESP32、嵌入式驱动开发岗位。
> 
> 学习完成后，应能独立解释 I²C 和 SPI 的通信原理、关键时序、电气特性、软件实现方法及常见故障排查思路。
> 
> **学习原则：不需要背 HAL 库函数，但必须理解底层通信时序。**

# 一、I²C 通信协议

## 1. I²C 的基本概念

I²C（Inter-Integrated Circuit）是一种**同步、串行、半双工、支持多设备共享总线**的通信协议。

通常使用两根信号线：

|信号线|全称|功能|
|---|---|---|
|SDA|Serial Data|双向传输数据|
|SCL|Serial Clock|提供同步时钟|

此外，设备之间还需要共地。

### 1.1 I²C 的特点

- 只需要 SDA 和 SCL 两根信号线。
    
- 支持多个设备连接在同一条总线上。
    
- 通过设备地址区分不同设备。
    
- 支持 7 位地址和 10 位地址，7 位最常见。
    
- SDA 是双向数据线，通常不能同时进行双向数据传输。
    
- 支持多个主控制器以及总线仲裁。
    
- 使用 ACK/NACK 应答机制。
    

常见速率：

|模式|最大速率|
|---|---|
|Standard-mode|100 kbit/s|
|Fast-mode|400 kbit/s|
|Fast-mode Plus|1 Mbit/s|
|High-speed mode|3.4 Mbit/s|

实际能够达到的速率取决于主机、从机、上拉电阻及总线电容等条件。

# 二、问题 1：I²C 一次完整通信的流程是什么？

这是最基础，也是最重要的问题。

## 2.1 一次通信包含哪些步骤？

以主机向从机写入数据为例：

```
START
   |
   v
发送从机地址 + 写标志
   |
   v
等待从机 ACK
   |
   v
发送寄存器地址
   |
   v
等待从机 ACK
   |
   v
发送数据
   |
   v
等待从机 ACK
   |
   v
STOP
```

总结：

**起始信号 → 地址 → 应答 → 数据传输 → 停止信号。**

需要注意：寄存器地址并不是 I²C 协议强制规定的字段，而是很多传感器采用的上层设备协议。

## 2.2 START：起始信号

I²C 总线空闲时：

```
SCL = 1
SDA = 1
```

当主机需要发起通信时：

**保持 SCL 为高电平，使 SDA 从高电平变为低电平。**

即：

```
SCL = HIGH

SDA：HIGH → LOW
```

这个动作就是 START。

它告诉所有从机：

> 总线上即将开始一次新的通信。

### 为什么用这个特殊时序表示 START？

因为 I²C 有一条基本规则：

**正常传输数据时，SCL 为高电平期间，SDA 必须保持稳定。**

只有在 SCL 为低电平期间，发送方才能正常改变 SDA 上的数据。

因此，SCL 为高时发生的 SDA 下降沿，就可以作为特殊的起始信号。

这也是为什么 I²C 不需要单独增加一根片选线。

## 2.3 STOP：停止信号

停止信号与起始信号相反。

保持 SCL 为高电平，使 SDA 从低电平变为高电平。

```
SCL = HIGH

SDA：LOW → HIGH
```

产生 STOP 后，这次通信结束，总线可以重新进入空闲状态。

### 面试追问

**为什么不能在 SCL 为高电平时随意改变 SDA？**

因为接收设备通常在 SCL 高电平期间读取数据。

如果 SDA 在此时变化，就可能破坏数据稳定性，而且可能被识别为 START 或 STOP。

---

## 2.4 I²C 地址是怎么发送的？

以常见的 7 位地址模式为例。

假设从机地址为：

```
0x68
```

其二进制为：

```
1101000
```

主机发送的第一个字节由两部分组成：

```
7 位从机地址 + 1 位 R/W
```

R/W 表示通信方向：

```
0：主机写入从机
1：主机读取从机
```

因此：

写操作：

```
1101000 0

= 11010000

= 0xD0
```

读操作：

```
1101000 1

= 11010001

= 0xD1
```

这里一定要区分：

- `0x68`：7 位设备地址。
    
- `0xD0`：总线上发送的地址字节，表示写操作。
    
- `0xD1`：总线上发送的地址字节，表示读操作。
    

### 非常经典的面试追问

**为什么设备手册写的是 0x68，但是逻辑分析仪上看到的是 0xD0？**

因为设备手册通常给出 7 位地址，而实际传输的地址字节还包含一个 R/W 位。

另外，部分逻辑分析仪的软件会直接解码并显示 7 位地址，因此具体显示格式要看分析软件的设置。

### STM32 HAL 的注意事项

很多 STM32 HAL I²C API 使用的 `DevAddress` 参数要求传入左移后的 7 位地址。

例如：

```
#define MPU6050_ADDR  (0x68U << 1)
```

但不同驱动 API 对地址参数的约定可能不同，不能一概而论。

---

## 2.5 结合 MPU6050 理解一次写操作

假设：

- MPU6050 的 7 位 I²C 地址为 `0x68`。
    
- 需要访问寄存器 `0x6B`。
    
- 向寄存器写入 `0x00`。
    

其通信过程为：

```
START
  |
  v
0xD0       从机地址 + 写标志
  |
  v
ACK
  |
  v
0x6B       寄存器地址
  |
  v
ACK
  |
  v
0x00       写入的数据
  |
  v
ACK
  |
  v
STOP
```

对应的软件调用可以抽象为：

```
I2C_Start();

I2C_WriteByte(0xD0);
I2C_WaitAck();

I2C_WriteByte(0x6B);
I2C_WaitAck();

I2C_WriteByte(0x00);
I2C_WaitAck();

I2C_Stop();
```

这段代码用于展示协议过程，实际驱动必须检查每次应答及超时结果。

### 面试回答模板

I²C 通信首先由主机产生 START 信号，然后发送从机地址和读写方向位，从机通过 ACK 表示应答。

之后主机和从机按照协议进行数据传输，每发送一个字节后都有第九个时钟周期用于 ACK/NACK。

通信完成后，由主机产生 STOP 信号释放总线。

---

## 2.6 I²C 读取寄存器为什么需要重复起始？

这是很值得深入理解的一点。

假设需要读取 MPU6050 的 `WHO_AM_I` 寄存器。

寄存器地址为：

```
0x75
```

一般采用下面的流程：

```
START
  |
  v
0xD0          地址 + 写
  |
  v
ACK
  |
  v
0x75          指定要读取的寄存器
  |
  v
ACK
  |
  v
Repeated START
  |
  v
0xD1          地址 + 读
  |
  v
ACK
  |
  v
读取 1 字节
  |
  v
NACK
  |
  v
STOP
```

注意：

**读取寄存器时，通常要先写入寄存器地址，然后再读取数据。**

因为主机首先需要告诉从机：

> 我要读取哪个寄存器？

指定寄存器后，再把传输方向切换为读取。

### 为什么使用 Repeated START？

Repeated START 称为重复起始信号。

它与普通 START 的电气时序基本相同，但它发生在尚未产生 STOP 的通信过程中。

主要作用：

1. 不释放总线。
    
2. 允许主机继续当前通信。
    
3. 可以切换读写方向。
    
4. 避免其他主机在两段操作之间获得总线控制权。
    

很多寄存器型设备的读取时序要求或推荐使用重复起始。

但是否允许先 STOP 再 START，需要看具体设备的数据手册。

# 三、问题 2：为什么 I²C 使用开漏输出，需要上拉电阻？

这是 I²C 最经典的电气原理问题。

## 3.1 什么是推挽输出？

普通 GPIO 经常使用推挽输出（Push-Pull）。

内部可以简单理解为存在两个受控开关：

```
          VDD
           |
        上拉开关
           |
           +------ GPIO
           |
        下拉开关
           |
          GND
```

输出高电平时，接通上拉通路。

输出低电平时，接通下拉通路。

因此，推挽输出既能主动输出高电平，也能主动输出低电平。

## 3.2 什么是开漏输出？

开漏输出（Open-Drain）通常只有主动下拉能力。

```
          VDD
           |
         Rpull
           |
           +------ GPIO
           |
        下拉开关
           |
          GND
```

两种状态：

**状态一：输出 0**

内部下拉晶体管导通。

```
GPIO → GND
```

引脚被拉到低电平。

**状态二：输出 1**

内部下拉晶体管关闭。

GPIO 不再主动拉低总线。

此时 GPIO 本身处于高阻状态。

如果外部存在上拉电阻，GPIO 所连接的总线才会被拉到高电平。

所以：

**开漏输出写 1，本质上是释放总线，而不是主动输出高电平。**

---

## 3.3 为什么 I²C 要使用开漏？

因为 I²C 是多设备共享总线。

假设主机和从机同时连接 SDA。

如果采用推挽输出：

```
主机：输出高电平
从机：输出低电平
```

可能形成供电端到地之间的低阻电流通路。

造成较大的冲突电流，严重时可能损坏器件。

而采用开漏输出：

```
主机：释放 SDA
从机：拉低 SDA
```

总线最终为低电平。

不会出现两个推挽输出相互对抗的情况。

### 线与（Wired-AND）

开漏总线的逻辑关系为：

```
设备 A    设备 B    总线状态

  1         1         1
  1         0         0
  0         1         0
  0         0         0
```

这里的 1 表示设备释放总线。

因此：

**只要有任意设备拉低 SDA，总线就是低电平。**

这叫线与。

### 为什么线与很重要？

它可以实现：

- 多设备共享总线。
    
- ACK 应答。
    
- 多主机仲裁。
    
- SCL 时钟拉伸。
    

例如：

主机发送完地址后释放 SDA。

从机可以主动拉低 SDA，产生 ACK。

如果主机仍然主动输出高电平，从机就无法安全地将 SDA 拉低。

---

## 3.4 为什么需要上拉电阻？

因为开漏输出只能主动拉低，不能主动拉高。

没有上拉电阻时，所有设备释放总线后，线路可能处于悬空状态。

高电平无法可靠建立。

所以需要：

```
3.3V
 |
 Rpull
 |
 +----------- SDA
 |
 +----------- 多个 I²C 设备
```

SCL 通常也采用类似的上拉结构。

### 上拉电阻越小越好吗？

不是。

上拉电阻过大：

- 总线电容充电慢。
    
- 上升沿变缓。
    
- 高速通信容易失败。
    

上拉电阻过小：

- 设备输出低电平时需要吸收更大的电流。
    
- 功耗增加。
    
- 可能超过器件允许的下拉电流。
    
- 低电平电压可能无法满足要求。
    

例如：

假设：

```
VDD = 3.3V
R = 4.7kΩ
```

忽略低电平残余电压时：

```
I ≈ 3.3 / 4700

I ≈ 0.70mA
```

如果采用：

```
R = 1kΩ
```

则：

```
I ≈ 3.3mA
```

实际选型要同时满足器件的低电平驱动能力和总线上升时间要求。

### 上拉电阻与总线电容

上升时间与上拉电阻、总线电容有关。

对于常用的电阻上拉模型：

```
tr ≈ 0.8473 × Rp × Cb
```

其中：

- `tr`：10% 到 90% 电平的上升时间。
    
- `Rp`：上拉电阻。
    
- `Cb`：总线等效电容。
    

因此：

**总线越长、挂载设备越多、电容越大，通常越需要关注上升时间。**

工程中常见 2.2kΩ、4.7kΩ、10kΩ 等上拉电阻，但不能认为某个阻值适合所有情况。

### 面试回答模板

I²C 使用开漏结构主要是为了支持多设备共享总线，避免不同设备同时驱动高低电平导致输出冲突。

开漏输出只能主动拉低电平，输出高电平时实际上是释放总线，因此需要外部上拉电阻建立高电平。

这种结构还可以实现线与逻辑，支持 ACK、时钟拉伸以及多主机仲裁。

# 四、问题 3：ACK 和 NACK 分别代表什么？

## 4.1 ACK/NACK 的定义

ACK：

```
Acknowledge
```

表示应答。

NACK：

```
Not Acknowledge
```

表示非应答。

在标准 I²C 通信中：

**每传输 8 位数据，后面跟随第 9 个时钟周期，用于 ACK/NACK。**

```
SCL：

1 2 3 4 5 6 7 8 9
                |
                +-- ACK/NACK
```

第九个时钟周期：

```
SDA = 0 → ACK

SDA = 1 → NACK
```

这里的 ACK/NACK 通常由接收方产生。

## 4.2 ACK 是怎么产生的？

以主机写数据为例：

1. 主机发送 8 位数据。
    
2. 主机释放 SDA。
    
3. 主机产生第九个时钟。
    
4. 从机将 SDA 拉低。
    
5. 主机检测 SDA 是否为低电平。
    

如果 SDA 为低：

```
ACK
```

如果 SDA 为高：

```
NACK
```

注意：

**I²C 的 ACK 不是另外发送一个字节，而是第九个时钟周期对应的总线状态。**

---

## 4.3 为什么主机读取最后一个字节后要发送 NACK？

这个问题非常适合面试。

因为读取数据时，发送方和接收方的角色发生了变化。

主机写数据：

```
主机：发送数据
从机：发送 ACK
```

主机读数据：

```
从机：发送数据
主机：发送 ACK/NACK
```

假设主机需要读取 3 字节：

```
从机发送 Byte1
主机发送 ACK

从机发送 Byte2
主机发送 ACK

从机发送 Byte3
主机发送 NACK

主机发送 STOP
```

主机对前两个字节发送 ACK，表示还希望继续接收数据。

最后一个字节后发送 NACK，表示：

> 我不需要继续接收数据了。

然后主机产生 STOP 或其他合法的后续总线操作。

### 非常重要

**NACK 不一定代表通信错误。**

例如：

- 地址阶段 NACK：可能没有设备响应。
    
- 数据阶段 NACK：可能设备暂时无法继续接收。
    
- 主机读取最后一个字节后发送 NACK：正常结束读取。
    

判断 NACK 是否异常，需要结合通信阶段。

---

## 4.4 面试官可能进一步问：I²C 为什么要有 ACK？

主要是为了让发送方知道接收方是否响应或是否愿意继续接收。

但是要注意：

ACK 只能表明接收方在协议层面给出了应答。

它不能保证：

- 业务数据一定正确。
    
- 数据已经成功写入非易失存储器。
    
- 设备内部操作已经完成。
    

如果需要更强的可靠性保证，通常还需要读取状态寄存器、回读校验或上层协议校验机制。

---

# 五、问题 4：软件 I²C 如何实现起始条件和停止条件？

这是你以前手写过软件 I²C 后，最值得重新掌握的内容。

## 5.1 软件 I²C 和硬件 I²C 的区别

硬件 I²C：

由 MCU 内部 I²C 外设自动完成部分时序控制。

CPU 主要负责：

- 配置外设。
    
- 设置地址。
    
- 准备发送和接收数据。
    
- 处理状态、错误及中断。
    

软件 I²C：

直接通过 GPIO 模拟 SDA、SCL 时序。

CPU 通过控制 GPIO 的电平变化完成通信。

例如：

```
SDA_LOW();
SCL_LOW();

SDA_RELEASE();
SCL_RELEASE();
```

其中：

```
LOW     ：主动拉低
RELEASE ：释放总线，由上拉电阻拉高
```

注意，这里没有直接使用 `SDA_HIGH()`，是为了强调开漏输出的实际行为。

---

## 5.2 软件 I²C 起始信号

时序：

```
初始：

SCL = 1
SDA = 1

第一步：
SDA = 0
SCL = 1

第二步：
SCL = 0
```

对应代码：

```
void I2C_Start(void)
{
    SDA_RELEASE();
    SCL_RELEASE();

    I2C_Delay();

    SDA_LOW();

    I2C_Delay();

    SCL_LOW();
}
```

这个示例假设：

- GPIO 已经配置为开漏输出。
    
- 外部存在合适的上拉电阻。
    
- 总线可以正常升高。
    
- 不考虑其他设备拉低总线的特殊情况。
    

实际可靠驱动还要检测 SCL 是否真的变高，避免忽略时钟拉伸或总线卡死。

---

## 5.3 软件 I²C 停止信号

时序：

```
第一步：
SCL = 0
SDA = 0

第二步：
SCL = 1
SDA = 0

第三步：
SCL = 1
SDA = 1
```

对应代码：

```
void I2C_Stop(void)
{
    SCL_LOW();
    SDA_LOW();

    I2C_Delay();

    SCL_RELEASE();

    I2C_Delay();

    SDA_RELEASE();

    I2C_Delay();
}
```

核心就是：

**在 SCL 为高电平期间，让 SDA 从低电平变为高电平。**

---

## 5.4 软件 I²C 如何发送一个字节？

I²C 通常先发送最高有效位 MSB。

例如：

```
0xA5 = 10100101
```

发送顺序：

```
1 → 0 → 1 → 0 → 0 → 1 → 0 → 1
```

软件实现：

```
void I2C_SendByte(uint8_t data)
{
    for (uint8_t i = 0; i < 8; i++)
    {
        SCL_LOW();

        if (data & 0x80U)
        {
            SDA_RELEASE();
        }
        else
        {
            SDA_LOW();
        }

        I2C_Delay();

        SCL_RELEASE();

        I2C_Delay();

        SCL_LOW();

        data <<= 1;
    }

    SDA_RELEASE();
}
```

解释：

```
data & 0x80U
```

检查最高位是否为 1。

```
data <<= 1;
```

每发送一位，就将下一位移动到最高位。

整个过程为：

```
设置 SDA
   |
   v
SCL 拉高
   |
   v
接收方读取数据
   |
   v
SCL 拉低
   |
   v
准备下一位
```

注意，这只是展示 8 位数据发送的核心逻辑。

真实软件 I²C 还应该在释放 SCL 后检查它是否真正升高，并处理超时。

---

## 5.5 软件 I²C 如何检测 ACK？

发送完一个字节后：

主机必须释放 SDA，让从机有机会拉低 SDA。

核心代码：

```
bool I2C_WaitAck(void)
{
    bool ack;

    SDA_RELEASE();

    I2C_Delay();

    SCL_RELEASE();

    I2C_Delay();

    ack = (SDA_READ() == 0);

    SCL_LOW();

    return ack;
}
```

如果：

```
SDA_READ() == 0
```

表示从机发送 ACK。

否则为 NACK。

### 关键问题

**为什么等待 ACK 前必须释放 SDA？**

因为 ACK 是接收方产生的。

如果发送方继续拉低 SDA，那么即使从机没有应答，主机也可能读取到低电平，误以为收到 ACK。

这属于非常典型的软件 I²C Bug。

---

## 5.6 软件 I²C 如何处理时钟拉伸？

Clock Stretching 称为时钟拉伸。

某些从机处理数据需要更多时间，会主动保持 SCL 低电平。

即使主机已经释放 SCL，线路也不会立即变高。

因此可靠实现不能简单假设：

```
SCL_RELEASE();
```

执行后 SCL 一定是高电平。

应该检查实际引脚状态：

```
bool I2C_WaitSCLHigh(void)
{
    uint32_t timeout = 10000;

    SCL_RELEASE();

    while (SCL_READ() == 0)
    {
        if (--timeout == 0)
        {
            return false;
        }
    }

    return true;
}
```

这里使用循环计数只是说明原理。

实际项目应根据时钟和编译环境使用定时器或可靠的时间基准设置超时，不能把循环次数直接等同于固定时间。

### 面试追问

**如果从机一直把 SCL 拉低怎么办？**

不能无限等待。

需要：

1. 设置超时时间。
    
2. 判断总线状态。
    
3. 记录错误信息。
    
4. 按照设备要求执行恢复操作。
    
5. 必要时复位设备或重新上电。
    

---

## 5.7 软件 I²C 的优缺点

|对比|软件 I²C|硬件 I²C|
|---|---|---|
|实现方式|GPIO 模拟|硬件控制器|
|灵活性|高|受外设能力限制|
|CPU 占用|通常较高|通常较低|
|高速通信|不太适合|更适合|
|时序控制|软件负责|硬件负责主要时序|
|调试|时序容易修改|需要结合外设状态|
|中断影响|对精确软件延时较敏感|通常更稳定|

### 面试回答模板

软件 I²C 通过 GPIO 模拟 SDA 和 SCL 的电平变化实现通信。

起始条件是在 SCL 为高电平时让 SDA 从高变低；停止条件是在 SCL 为高电平时让 SDA 从低变高。

数据传输时，需要在 SCL 低电平期间设置 SDA，并在 SCL 高电平期间保持数据稳定。

发送完 8 位数据后，发送方释放 SDA，由接收方在第九个时钟周期产生 ACK 或 NACK。

---

# 六、问题 5：如果 I²C 设备一直不应答，如何排查？

这是实际开发中非常重要的问题。

建议按照下面的顺序排查。

## 6.1 第一层：检查硬件

首先检查：

- 设备是否正常供电。
    
- MCU 与设备是否共地。
    
- SDA、SCL 有没有接反。
    
- SDA、SCL 是否有合适的上拉电阻。
    
- 信号电平是否兼容。
    
- 设备复位引脚是否处于正常状态。
    
- 设备是否已经完成上电初始化。
    

尤其需要注意电压。

例如：

STM32 使用 3.3V，外部传感器使用不同的供电电压时，不能默认所有引脚都可以直接连接。

需要检查芯片的数据手册。

## 6.2 第二层：检查设备地址

最常见的问题之一就是 7 位地址和左移后的地址混淆。

例如：

```
7 位地址：0x68

写地址字节：0xD0

读地址字节：0xD1
```

对于 MPU6050，还应该检查 AD0 引脚配置。

常见地址：

```
AD0 = 0 → 0x68

AD0 = 1 → 0x69
```

具体设备以数据手册为准。

## 6.3 第三层：使用逻辑分析仪检查波形

将逻辑分析仪连接到：

```
CH0 → SCL

CH1 → SDA

GND → 系统 GND
```

然后观察：

### 情况一：完全没有 SCL 时钟

可能原因：

- I²C 外设没有启动。
    
- GPIO 配置错误。
    
- 软件没有执行发送函数。
    
- 总线被拉低。
    
- 程序卡在其他位置。
    

### 情况二：有时钟，但地址后出现 NACK

可能原因：

- 地址不正确。
    
- 设备没有供电。
    
- 设备没有退出复位。
    
- SDA 线路异常。
    
- 电平或时序不满足要求。
    
- 设备当前无法响应。
    

### 情况三：SDA 一直是高电平

可能原因：

- SDA 断线。
    
- 从机没有驱动 SDA。
    
- 地址错误导致从机没有应答。
    
- 上拉存在但通信未正确进行。
    

### 情况四：SDA 一直是低电平

可能原因：

- 某个设备持续拉低 SDA。
    
- GPIO 被错误配置成持续输出低电平。
    
- 从机状态机异常。
    
- 线路短路。
    

### 情况五：SCL 一直是低电平

可能原因：

- 设备正在进行时钟拉伸。
    
- 某个设备异常拉低 SCL。
    
- 主机没有释放 SCL。
    
- 硬件线路故障。
    

注意：逻辑分析仪主要观察数字电平和时序。

如果怀疑上升沿过慢、电平幅值不正确、振铃等模拟信号问题，应该使用示波器进一步检查。

---

## 6.4 I²C 总线卡死怎么办？

例如 SDA 被从机一直拉低。

某些情况下，可以尝试总线恢复操作：

1. 确认 SCL 能够被拉高。
    
2. 主机释放 SDA。
    
3. 尝试产生最多 9 个 SCL 时钟脉冲。
    
4. 观察从机是否释放 SDA。
    
5. 条件允许时产生 STOP。
    
6. 如果无法恢复，考虑设备复位或重新上电。
    

但这不是所有故障的通用解决方案。

如果线路发生物理短路，发送时钟没有意义。

### 面试回答模板

如果 I²C 设备不应答，我会首先检查供电、共地、GPIO 配置和上拉电阻，然后确认从机地址以及读写位是否正确。

接着使用逻辑分析仪观察 SCL 和 SDA，重点检查 START、地址发送和第九个时钟周期的 ACK。

如果地址正确但持续 NACK，我会检查器件复位状态、上电时序和通信速率。

如果发现总线被拉低，则进一步判断是时钟拉伸、从机异常还是硬件故障，必要时按照器件要求执行总线恢复或设备复位。

---

# 七、SPI 通信协议

## 1. SPI 的基本概念

SPI（Serial Peripheral Interface）是一种常见的同步串行通信接口。

典型四线 SPI 具有：

- 同步通信。
    
- 全双工通信能力。
    
- 由主机提供时钟。
    
- 使用片选信号选择从机。
    
- 通常具有较高的数据传输速率。
    

SPI 常用于：

- 外部 Flash。
    
- ADC、DAC。
    
- 显示屏。
    
- IMU 传感器。
    
- 高速数据采集设备。
    

SPI 的具体帧格式、命令和读写规则通常由设备厂商规定。

---

# 八、问题 1：SPI 的四根信号线分别有什么作用？

典型四线 SPI 使用：

|信号线|全称|功能|
|---|---|---|
|SCLK|Serial Clock|时钟|
|MOSI|Master Out Slave In|主机发送、从机接收|
|MISO|Master In Slave Out|从机发送、主机接收|
|CS/SS|Chip Select|片选信号|

有些芯片使用 SDI、SDO 等名称，需要结合设备视角判断方向。

## 8.1 SPI 的连接方式

```
        STM32                 SPI Flash

        SCLK ----------------> SCLK

        MOSI ----------------> MOSI

        MISO <---------------- MISO

        CS   ----------------> CS

        GND  ----------------- GND
```

主机产生时钟。

主机通过 MOSI 发送数据。

从机通过 MISO 返回数据。

CS 用于选择当前通信的设备。

## 8.2 CS 的作用

大部分常见 SPI 设备使用低电平有效的 CS。

```
CS = 1：未选中

CS = 0：选中
```

一次典型通信：

```
CS 拉低
   |
   v
发送命令
   |
   v
发送或接收数据
   |
   v
CS 拉高
```

### 面试追问：SPI 为什么需要 CS？

因为 SPI 通常没有像 I²C 那样统一的总线地址机制。

当多个从机共享 SCLK、MOSI、MISO 时，主机可以使用不同的 CS 信号选择需要通信的设备。

例如：

```
             STM32
               |
       +-------+-------+
       |       |       |
      CS1     CS2     CS3
       |       |       |
     Flash    IMU     ADC
```

常规 SPI 多从机设计中，同一时刻通常只选中一个设备。

否则多个从机可能同时驱动 MISO，造成总线冲突。

### 注意

CS 的有效电平、建立时间、保持时间，以及是否允许在命令和数据之间释放 CS，都要根据具体器件手册确定。

---

# 九、问题 2：SPI 为什么能够实现全双工？

核心原因是：

**SPI 具有独立的 MOSI 和 MISO 数据通道。**

因此，在主机发送数据时，从机也能够同时向主机返回数据。

## 9.1 从移位寄存器理解全双工

可以把主机和从机内部简化成两个移位寄存器：

```
       主机                        从机

    +---------+                +---------+
    |  TX/RX  | ----MOSI-----> |  TX/RX  |
    | 移位寄存器| <----MISO----- | 移位寄存器|
    +---------+                +---------+
         ^                          ^
         |                          |
         +----------SCLK------------+
```

随着时钟脉冲产生：

- 主机通过 MOSI 移出一位。
    
- 从机通过 MOSI 接收一位。
    
- 从机通过 MISO 移出一位。
    
- 主机通过 MISO 接收一位。
    

经过 8 个时钟周期，典型 8 位数据帧就完成了双向移位传输。

因此：

**SPI 的发送和接收不是两个完全独立的过程，而是在时钟驱动下同时发生的。**

---

## 9.2 SPI 为什么读数据也需要发送数据？

这是一个很经典的面试问题。

假设主机需要从 SPI Flash 中读取设备 ID。

主机首先发送：

```
0x9F
```

这是很多 SPI NOR Flash 使用的 JEDEC ID 读取命令。

然后主机需要继续产生时钟，让从机输出 ID 数据。

但 SPI 的时钟由主机提供。

如果主机不再产生时钟，从机就无法继续发送数据。

因此主机需要发送一些占位数据：

```
0x00
```

或者：

```
0xFF
```

这些数据通常称为 Dummy Data。

例如：

```
MOSI：

0x9F  0x00  0x00  0x00

MISO：

XXXX  ID1   ID2   ID3
```

这里 `XXXX` 代表命令阶段收到的数据不作为有效 ID。

实际使用的占位字节和数据格式取决于器件。

### 面试回答模板

SPI 能实现全双工，是因为 MOSI 和 MISO 是两条独立的数据线，主从设备可以在相同的时钟周期内同时移出和接收数据。

SPI 由主机提供时钟，因此主机即使只是读取数据，也需要继续发送占位字节来产生时钟，让从机把数据移出来。

---

# 十、问题 3：CPOL 和 CPHA 分别是什么？

这是 SPI 面试最重要的知识点之一。

必须真正理解，而不是只记住四种模式。

## 10.1 CPOL：时钟极性

CPOL（Clock Polarity）决定：

**SPI 时钟空闲时是什么电平。**

```
CPOL = 0

SCLK 空闲为低电平
```

```
CPOL = 1

SCLK 空闲为高电平
```

CPOL 只决定时钟空闲状态，不直接决定数据在哪个边沿采样。

## 10.2 CPHA：时钟相位

CPHA（Clock Phase）决定：

**在一个时钟周期的第几个有效边沿采样数据。**

这里需要理解两个概念：

- Leading Edge：第一个时钟边沿。
    
- Trailing Edge：第二个时钟边沿。
    

对于：

```
CPOL = 0
```

时钟空闲为低电平。

因此：

```
第一个边沿：上升沿

第二个边沿：下降沿
```

对于：

```
CPOL = 1
```

时钟空闲为高电平。

因此：

```
第一个边沿：下降沿

第二个边沿：上升沿
```

CPHA 的作用：

```
CPHA = 0

第一个边沿采样数据
```

```
CPHA = 1

第二个边沿采样数据
```

在常见 SPI 时序中，数据在一个边沿更新，在另一个边沿采样。

这样可以让数据在采样时保持稳定。

---

## 10.3 SPI 四种工作模式

|模式|CPOL|CPHA|空闲时钟|采样边沿|
|---|---|---|---|---|
|Mode 0|0|0|低|上升沿|
|Mode 1|0|1|低|下降沿|
|Mode 2|1|0|高|下降沿|
|Mode 3|1|1|高|上升沿|

这张表需要掌握。

但比背表更重要的是能够自己推导。

### Mode 0

```
CPOL = 0
CPHA = 0
```

空闲低电平。

第一个边沿是上升沿。

CPHA 为 0，意味着第一个边沿采样。

所以：

```
上升沿采样
下降沿更新
```

### Mode 1

```
CPOL = 0
CPHA = 1
```

空闲低电平。

第一个边沿是上升沿。

CPHA 为 1，意味着第二个边沿采样。

所以：

```
上升沿更新
下降沿采样
```

### Mode 2

```
CPOL = 1
CPHA = 0
```

空闲高电平。

第一个边沿是下降沿。

CPHA 为 0，意味着第一个边沿采样。

所以：

```
下降沿采样
上升沿更新
```

### Mode 3

```
CPOL = 1
CPHA = 1
```

空闲高电平。

第一个边沿是下降沿。

CPHA 为 1，意味着第二个边沿采样。

所以：

```
下降沿更新
上升沿采样
```

### 特别注意 CPHA = 0

由于第一个时钟边沿就需要采样，因此第一位数据必须在第一个采样边沿到来之前建立并保持稳定。

这也是为什么理解 CPHA 不能只靠背模式表。

---

## 10.4 如果 CPOL、CPHA 配置错误，会发生什么？

可能出现：

- 数据位错位。
    
- 读取数据不稳定。
    
- 部分字节正确、部分字节错误。
    
- 数据全部错误。
    
- 在某些时序条件下表现为偶发故障。
    

例如：

从机在上升沿采样。

但主机恰好在上升沿更新数据。

这样从机可能在数据变化的瞬间采样，造成建立时间或保持时间不满足要求。

### 面试回答模板

CPOL 是时钟极性，用于决定 SPI 空闲时钟是高电平还是低电平。

CPHA 是时钟相位，决定在第一个还是第二个时钟边沿采样数据。

CPOL 和 CPHA 的组合形成四种 SPI 工作模式。

主机必须根据从机数据手册配置正确模式，否则可能出现数据采样错误。

---

# 十一、问题 4：SPI 和 I²C 有什么区别？

## 11.1 核心对比

|对比项目|I²C|SPI|
|---|---|---|
|通信方式|同步串行|同步串行|
|典型数据方向|半双工|全双工|
|主要信号线|SDA、SCL|MOSI、MISO、SCLK、CS|
|设备选择|地址|片选|
|应答机制|协议定义 ACK/NACK|没有统一的 ACK/NACK|
|电气结构|通常开漏加上拉|通常推挽|
|多设备扩展|共用两根信号线|通常增加 CS|
|时钟|主机产生|主机产生|
|传输速度|常见 100k/400k|通常可达到更高速度|
|协议复杂度|相对较复杂|基础时序相对简单|
|多主机|标准支持|常规 SPI 不提供统一仲裁|
|典型用途|配置、低速传感器|Flash、显示、高速传感器|

## 11.2 为什么 SPI 通常比 I²C 快？

主要原因包括：

**第一：SPI 通常使用推挽输出。**

推挽输出可以主动拉高、拉低信号。

相比常见电阻上拉 I²C，总线的上升速度通常更容易提高。

**第二：SPI 没有标准 I²C 的地址和逐字节 ACK 开销。**

I²C 每发送 8 位数据，通常还需要第九个时钟完成 ACK/NACK。

SPI 的基础传输没有这个统一要求。

**第三：SPI 可以全双工。**

在同一时钟周期内可以同时传输两个方向的数据。

但是需要注意：

**全双工不等于实际业务的有效吞吐量一定翻倍。**

很多 SPI 设备的命令和数据阶段仍然只能按照规定的顺序进行。

实际速率还受器件最高频率、线路长度、负载和时序要求限制。

---

## 11.3 为什么很多低速传感器使用 I²C？

因为 I²C 接线简单。

多个设备可以共享 SDA 和 SCL。

例如：

```
STM32
  |
  +------- I²C BUS --------+
  |           |            |
 MPU6050    BMP280       EEPROM
```

只需要两根主要信号线，就可以访问多个地址不同的设备。

比较适合：

- 传感器配置。
    
- 低速数据采集。
    
- EEPROM。
    
- 板级管理。
    

## 11.4 为什么高速传感器和 Flash 经常使用 SPI？

因为 SPI 通常可以提供更高的传输速率。

而且全双工和连续时钟传输能够满足很多高速设备的要求。

例如：

- 外部 NOR Flash。
    
- 高速 ADC。
    
- 高刷新率显示屏。
    
- 高频率采样的 IMU。
    

需要注意，某些器件同时支持 SPI 和 I²C，实际使用哪个接口取决于带宽、引脚资源和硬件设计。

---

## 11.5 面试追问：I²C 为什么需要 ACK，而 SPI 不需要？

I²C 是共享总线协议。

主机通过地址选择设备，并通过 ACK/NACK 判断设备是否响应以及是否继续接收数据。

而 SPI 通常直接使用 CS 选择从机。

基础 SPI 协议只规定相对简单的时钟和数据传输机制，没有统一的逐字节 ACK 机制。

但是：

**SPI 没有统一 ACK，不代表 SPI 通信不能实现可靠性检测。**

例如某些设备或上层协议可以定义：

- 状态寄存器。
    
- CRC。
    
- 数据回读。
    
- 错误标志。
    
- 命令响应。
    

这些机制由具体设备协议实现。

---

# 十二、问题 5：如果 SPI 接收数据异常，如何使用逻辑分析仪排查？

这个问题主要考查实际工程调试能力。

## 12.1 第一步：检查硬件连接

首先检查：

```
SCLK
MOSI
MISO
CS
GND
```

确认：

- 主从设备共地。
    
- 电源电压正确。
    
- MOSI、MISO 没有接反。
    
- CS 接线正确。
    
- GPIO 复用功能正确。
    
- 引脚电压兼容。
    

对于 STM32，还需要检查具体引脚是否配置到了正确的 SPI 复用功能。

---

## 12.2 第二步：连接逻辑分析仪

例如：

```
CH0 → SCLK

CH1 → MOSI

CH2 → MISO

CH3 → CS

GND → 系统 GND
```

通过逻辑分析仪观察四根信号线。

建议采样率明显高于 SPI 时钟频率。

如果设备使用较高的 SPI 时钟频率，普通低速逻辑分析仪可能无法可靠捕获波形。

一般可以先降低 SPI 通信速率进行定位。

---

## 12.3 第三步：检查 CS

正常情况下，典型低有效 CS 的通信过程：

```
CS 拉低
   |
   v
SCLK 开始输出
   |
   v
MOSI/MISO 传输数据
   |
   v
CS 拉高
```

如果 CS 没有正确拉低，从机可能完全忽略主机发送的数据。

如果 CS 在命令与数据之间被意外拉高，从机可能将后续数据当作一条新的命令。

所以需要重点检查：

- CS 极性。
    
- CS 下降沿与第一个时钟之间的时间。
    
- CS 是否在整个事务中保持有效。
    
- 最后一个时钟结束后 CS 的保持时间。
    

---

## 12.4 第四步：检查 SCLK

观察：

1. 是否存在时钟。
    
2. 时钟频率是否正确。
    
3. 空闲电平是否正确。
    
4. 时钟数量是否符合预期。
    

例如：

如果发送一个 8 位字节：

```
通常需要 8 个时钟周期
```

如果没有时钟：

可能是 SPI 外设没有启动，也可能是主机没有发起传输。

如果时钟频率超过从机支持的最大值，就可能导致通信异常。

---

## 12.5 第五步：检查 MOSI

检查主机发送的数据是否正确。

例如准备发送：

```
0x9F
```

二进制：

```
10011111
```

如果采用 MSB First，应该按最高位到最低位的顺序发送。

如果逻辑分析仪解析出的数据不正确，需要检查：

- 发送缓冲区内容。
    
- 数据位宽。
    
- MSB/LSB 顺序。
    
- CPOL/CPHA。
    
- SPI 外设配置。
    

---

## 12.6 第六步：检查 MISO

MISO 是从机发送给主机的数据。

如果读出来始终是：

```
0xFF
```

可能原因：

- MISO 被上拉或保持高电平。
    
- 从机没有被选中。
    
- 从机没有驱动 MISO。
    
- MISO 接线异常。
    
- 命令格式错误。
    

如果始终是：

```
0x00
```

可能原因：

- MISO 被拉低。
    
- 从机没有正确响应。
    
- 电路异常。
    
- 命令或工作模式错误。
    

但要注意：

**0xFF 和 0x00 本身不能唯一确定故障原因。**

它们只是排查线索。

---

## 12.7 第七步：检查 SPI 工作模式

在逻辑分析仪中配置：

```
CPOL
CPHA
Bit Order
Data Width
CS Polarity
```

然后重新解析数据。

如果模式设置错误：

即使波形看起来正常，软件解码出来的数据也可能错误。

### 一个经典场景

主机使用：

```
Mode 0
```

从机要求：

```
Mode 3
```

主机和从机对时钟空闲极性、采样边沿的要求不同。

这可能造成通信数据错误。

解决方式不是盲目增加延时，而是先检查器件手册，正确设置 SPI 模式。

---

## 12.8 如果逻辑分析仪显示正常，但 MCU 读取错误怎么办？

需要继续区分：

**总线数据正确，不代表 MCU 软件正确读取和处理了数据。**

还需要检查：

- SPI 接收缓冲区是否正确。
    
- DMA 是否完成。
    
- 缓冲区是否发生覆盖。
    
- 接收长度是否正确。
    
- 是否错误处理了命令阶段接收的无效数据。
    
- 是否存在并发访问。
    
- 是否正确处理多个字节的数据顺序。
    

例如：

如果使用 DMA 接收数据，缓存一致性、DMA 缓冲区生命周期等问题也可能造成软件读到错误内容，具体取决于 MCU 架构。

### 面试回答模板

SPI 接收异常时，我会先检查供电、接线和 GPIO 配置，再使用逻辑分析仪同时采集 CS、SCLK、MOSI、MISO。

首先确认 CS 是否正确选中从机，然后检查时钟频率和 CPOL、CPHA 配置，接着验证 MOSI 发送的命令是否正确，并观察 MISO 是否返回预期数据。

如果实际总线数据正确，但软件读取结果错误，我会进一步检查接收缓冲区、DMA、中断、数据位宽和数据处理逻辑。

# 十三、进阶追问：面试官还可能考什么？

## 1. I²C 为什么可以多主机？

因为 I²C 使用开漏结构和线与逻辑，可以实现总线仲裁。

在多主机模式下：

如果某个主机尝试发送 1，但实际读取 SDA 为 0，说明其他主机正在发送 0。

在符合仲裁条件的情况下，该主机可以判断自己失去仲裁权。

因为 0 在开漏总线上具有优先性。

## 2. I²C 为什么可以时钟拉伸？

因为 SCL 也是共享线路。

当从机需要暂停通信时，可以保持 SCL 为低电平。

主机释放 SCL 后，如果发现线路仍然为低，就需要等待或执行超时处理。

并非所有设备都支持或使用时钟拉伸。

## 3. SPI 是否一定是四根线？

不是。

典型全双工 SPI 使用 SCLK、MOSI、MISO、CS 四根信号线。

但还存在：

- 三线 SPI。
    
- 单向 SPI。
    
- 半双工 SPI。
    
- Dual SPI。
    
- Quad SPI。
    
- Octal SPI。
    

不同接口的数据线配置和时序可能不同。

## 4. SPI 能不能使用 DMA？

可以。

例如 STM32 SPI 可以配合 DMA，实现数据自动传输。

优势：

- 减少 CPU 逐字节搬运数据的开销。
    
- 提高连续数据传输效率。
    
- 方便进行较大的数据块传输。
    

但 DMA 并不能自动解决 CS 时序、缓存管理和任务同步问题。

## 5. 软件 I²C 为什么可能受到中断影响？

因为软件 I²C 依赖 CPU 执行 GPIO 操作和延时。

如果通信过程中发生中断，可能拉长 SCL 高电平或低电平时间。

对于普通低速 I²C，这不一定立即造成错误，因为协议允许一定程度的时序延长。

但仍然可能导致：

- 通信速率不稳定。
    
- 超时。
    
- 不满足某些设备的特殊时序要求。
    
- 依赖软件定时的驱动出现问题。
    

所以不能简单认为软件 I²C 遇到中断就一定通信失败。

# 十四、面试速记：10 个问题的核心答案

| 问题           | 必须记住的核心                                 |
| ------------ | --------------------------------------- |
| I²C 通信流程     | START → 地址 → ACK → 数据 → ACK/NACK → STOP |
| 为什么使用开漏      | 防止输出冲突，实现共享总线和线与                        |
| ACK/NACK     | 第九个时钟周期，低为 ACK，高为 NACK                  |
| 软件 I²C       | GPIO 模拟 SDA/SCL 时序                      |
| I²C 不应答      | 供电 → 接线 → 上拉 → 地址 → 时序 → 波形             |
| SPI 四根线      | SCLK、MOSI、MISO、CS                       |
| SPI 为什么全双工   | MOSI 和 MISO 独立，能够同时移位收发                 |
| CPOL/CPHA    | CPOL 决定空闲电平，CPHA 决定采样边沿                 |
| SPI 与 I²C 区别 | 片选与寻址、全双工与半双工、推挽与开漏                     |
| SPI 故障排查     | CS → SCLK → MOSI → MISO → 软件接收          |
